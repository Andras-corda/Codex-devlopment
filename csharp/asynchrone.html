3 · Programmation asynchrone

Gérer les opérations qui attendent — réseau, disque, base de données — sans bloquer le thread ni figer l'application.

Le problème

Un appel réseau prend 200 ms. En synchrone, le thread reste immobilisé pendant ce temps : il ne peut ni traiter une autre requête, ni redessiner l'interface. L'asynchrone rend le thread pendant l'attente et le reprend quand la réponse arrive.

Task & Task<T>

Une Task représente une opération en cours ou à venir. Task = « ça finira » ; Task<T> = « ça produira un T ». C'est l'équivalent de la Promise d'autres langages.

État d'une TaskSens
Running / WaitingForActivationen cours
RanToCompletionterminée avec succès (résultat disponible)
Faultedterminée sur exception
Canceledannulée via un CancellationToken

async / await

  1. async sur une méthode = « elle contient des await ». Elle renvoie Task, Task<T> (ou ValueTask).
  2. await devant une Task = « suspends-toi ici jusqu'au résultat, sans bloquer le thread ; reprends ensuite à la ligne suivante ».
  3. Le compilateur transforme la méthode en machine à états : tout ce qui suit un await devient une continuation exécutée au retour.
Top-level await

Depuis .NET 6, Program.cs accepte await directement. Ailleurs, seule une méthode async peut l'utiliser. Convention : suffixe Async pour ces méthodes.

Lancer plusieurs tâches en parallèle

Ne pas await tout de suite : on démarre plusieurs Tasks, puis on attend le lot.

Parallélisme borné

10 000 appels d'un coup vont saturer le réseau. Limiter la concurrence avec SemaphoreSlim, Parallel.ForEachAsync (option MaxDegreeOfParallelism) ou System.Threading.Channels.

Règle d'or

async all the way : si une méthode appelle de l'async, elle-même devient async. Ne « recolle » jamais du synchrone avec .Result.
