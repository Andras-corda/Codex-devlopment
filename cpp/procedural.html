1 · Procédural

Variables, types, portée, opérateurs, décisions, boucles, procédures et fonctions — la base de tout programme C++ console.

Variables

Une variable est un espace de stockage en mémoire ; son type détermine la valeur qu'elle peut contenir. Le qualificateur const rend un identifiant en lecture seule — utile pour protéger une valeur d'un changement accidentel, ou pour donner un nom symbolique à une valeur fixe.

Les variables ne sont PAS initialisées par défaut

Contrairement à d'autres langages, déclarer int c; sans lui donner de valeur laisse un contenu indéterminé (ce qui se trouvait déjà à cet endroit en mémoire). Lire cette variable avant de l'avoir assignée est un bug classique — toujours initialiser à la déclaration par réflexe.

Constantes : const & constexpr

Une variable const ne peut plus être modifiée après son initialisation : toute tentative est une erreur de compilation, pas un bug découvert en jeu. C'est une promesse vérifiée par le compilateur — et une information pour le lecteur (« cette valeur ne bouge pas »).

constexpr : connue à la compilation

constexpr va plus loin : la valeur doit être calculable pendant la compilation. Elle peut alors servir là où le compilateur exige une constante — taille d'un tableau, étiquette de case, paramètre de template.

Modifiable ?Valeur connueUsage

Chasser les « nombres magiques »

if (speed > 600.0) ne dit pas ce que vaut 600. constexpr double MAX_SPEED = 600.0; donne un nom à la valeur, et un seul endroit à changer. Préférer aussi constexpr à #define MAX_SPEED 600.0 : une macro n'a ni type, ni portée — c'est un simple remplacement de texte avant la compilation.

const, pointeurs et références

Avec un pointeur, const peut protéger la valeur pointée, le pointeur lui-même, ou les deux. Astuce : lire la déclaration de droite à gauche.

Réflexe de const-correctness : tout ce qui n'a pas à changer est marqué const — variables locales, paramètres passés par référence (const std::string&, voir Procédures & fonctions), et plus tard les méthodes de classe qui ne modifient pas l'objet (int GetHealth() const, omniprésent dans le code C++ d'Unreal Engine).

Pour un contrôle précis de la taille (flags, couleurs, id de texture), C++ propose aussi uint8_t, uint16_t, uint32_t… (bibliothèque <cstdint>) — voir 2 · Manipulation de bits.

Portée (scope)

Les accolades { } délimitent une portée. Une variable déclarée dans une portée interne peut masquer (shadow) une variable de même nom d'une portée externe — l'inverse n'est pas possible.

Incrément & décrément

++ ajoute 1 à une variable, -- retire 1. Seuls, hp++; et ++hp; font exactement la même chose. La différence n'apparaît que quand l'opération est utilisée dans une expression : faut-il lire la valeur avant ou après le changement ?

Dans les boucles

i++ ou ++i dans un for ?

Pour un int, aucune différence : la valeur renvoyée n'est lue par personne, le compilateur produit le même code. Beaucoup de développeurs C++ prennent quand même l'habitude de ++i : sur des objets plus lourds (les itérateurs des conteneurs), le post-incrément doit fabriquer une copie de l'ancienne valeur pour la renvoyer.

Pièges

Ne pas modifier et relire la même variable dans une seule expression : a++ + a++ ou arr[i] = i++ ont un résultat indéfini ou peu lisible — faire l'incrément sur sa propre ligne. Attention aux non-signés : un uint8_t ammo = 0; auquel on fait ammo-- ne devient pas -1 mais 255 (il « fait le tour ») — toujours tester if (ammo > 0) avant de décrémenter. Et un int incrémenté au-delà de sa valeur maximale est un comportement indéfini.

Évaluation paresseuse (court-circuit)

&& et || s'arrêtent dès que le résultat est connu : dans A && B, si A est faux, B n'est jamais évalué ; dans A || B, si A est vrai non plus. C'est ce qui rend sûr ptr != nullptr && ptr->isAlive(). Un exemple de jeu : bool canOpenDoor = doorDistance < maxDistance && (!doorLocked || hasKey);

Ne jamais comparer des flottants avec ==

0.1 + 0.2 == 0.3 vaut false : la représentation binaire des flottants introduit de minuscules erreurs d'arrondi. Teste plutôt que l'écart est suffisamment petit (std::abs(a - b) < epsilon).

Prise de décision

Un if ne choisit pas forcément une branche d'affichage : il peut aussi modifier l'état du programme.

if vs switch

if pour évaluer des conditions ; switch pour choisir parmi plusieurs valeurs discrètes connues (entiers, char, enum — pas de std::string). Le gain est surtout en lisibilité : le compilateur peut en faire une table de saut, mais il optimise souvent une chaîne de if tout aussi bien. Le break arrête la comparaison — l'oublier fait « tomber » l'exécution dans le case suivant (fallthrough), parfois volontaire (cases groupés).

enum class crée un ensemble nommé de valeurs commençant à 0 par défaut — plus sûr qu'un simple enum (pas de conversion implicite en entier, les noms restent qualifiés par Item::). Le : uint8_t fixe la taille sur un octet : c'est exactement ce que fait Unreal pour les enums Blueprint (UENUM(BlueprintType) enum class … : uint8).

Plusieurs cases, un seul traitement

Sans break, l'exécution « tombe » dans le case suivant : case Item::RED_KEY: case Item::BLUE_KEY: std::cout << "A key"; break; traite les deux clés pareil.

Boucles imbriquées

Une boucle interne s'exécute en entier à chaque itération de la boucle externe — utile pour parcourir une grille 2D (for (y) { for (x) { ... } }).

Exemple complet : survivre à un combat

Tout ce qui précède dans un seul programme : une const, des booléens, des if, des opérateurs composés et une boucle while. Le héros encaisse une attaque par tour ; son bouclier divise les dégâts par deux, et une potion le sauve automatiquement s'il tombe à 0.

Pourquoi turn - 2 ?

À la sortie du while, turn a été incrémenté une fois de trop (après le dernier tour), et ce dernier tour est celui où le héros meurt : il n'a donc survécu qu'à turn - 2 tours. Avec ces valeurs : 9 tours survécus, mort au 10e. Ce genre de décalage d'un (off-by-one) est l'erreur de boucle la plus courante — toujours dérouler le premier et le dernier tour à la main.

Procédures & fonctions

Une fonction regroupe des instructions sous un nom réutilisable. Elle reçoit des paramètres et peut retourner une valeur. En C++ il n'y a pas de mot-clé séparé pour une procédure : c'est simplement une fonction de type void, qui agit (affiche, modifie un état) sans rien renvoyer.

Type de retourAppelBon pour
Procédurevoidinstruction seule : printHealth(hp);une action — afficher, modifier, sauvegarder
Fonctionint, double, bool…dans une expression : int d = damage(10, 2);calculer et renvoyer un résultat
Toujours retourner une valeur

Une fonction non-void doit atteindre un return sur tous les chemins (chaque branche d'un if). Sinon le comportement est indéfini — le compilateur ne fait qu'avertir. Dans une procédure, return; (sans valeur) permet de sortir plus tôt.

Déclaration (prototype) & définition

Le compilateur lit le fichier de haut en bas : une fonction doit être connue avant d'être appelée. Soit on la définit au-dessus de main(), soit on écrit son prototype (signature terminée par ;) en haut — typiquement dans un .h — et le corps plus loin.

Passage par valeur, par référence, par référence constante

Par défaut, un paramètre est une copie : modifier le paramètre ne change pas la variable de l'appelant. Avec &, le paramètre devient un alias de la variable d'origine.

Paramètres par défaut & surcharge

Le type de retour ne suffit pas

Deux surcharges doivent différer par leurs paramètres (nombre ou types). Deux fonctions qui ne diffèrent que par le type de retour ne compilent pas.

Récursivité

Une fonction peut s'appeler elle-même, à condition d'avoir un cas de base qui arrête les appels. Chaque appel empile ses propres variables locales sur la pile (stack) ; sans cas de base, on obtient un stack overflow.
