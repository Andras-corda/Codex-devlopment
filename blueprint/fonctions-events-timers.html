8 · Fonctions, events & timers

Organiser le code d'un Blueprint et le faire réagir dans le temps : fonctions pour calculer, events pour réagir, macros pour factoriser des bouts de flux, timers pour planifier. Le tableau comparatif d'ensemble est dans l'accueil ; cette page détaille chacun.

Fonctions

Une fonction est un graphe à part, appelé depuis ailleurs, qui s'exécute d'un seul bloc (dans la même frame) puis rend la main. Création : panneau My Blueprint → Functions → +.

ÉlémentÀ savoir
Entrées / sortiesajoutées dans les Details de la fonction. Les sorties se renseignent sur le Return Node ; on peut en avoir plusieurs (un par chemin). Une sortie jamais renseignée renvoie sa valeur par défaut (0, false, None) — sans erreur
Pass-by-Reference (case sur une entrée)le paramètre devient un alias de la variable de l'appelant (pin en losange) : la fonction la modifie directement, sans copie. Sinon l'entrée est une copie
Valeur par défaut d'une entréeutilisée quand la broche n'est pas branchée à l'appel
Variables localessection Local Variables du panneau My Blueprint : créées à chaque appel, détruites à la sortie, remises à leur valeur initiale à l'appel suivant
Access SpecifierPublic (appelable de partout), Protected (ce Blueprint et ses enfants), Private (ce Blueprint seulement)
Pure / ConstPure retire les pins d'exécution (calcul sans effet de bord, réévalué à chaque lecture) ; Const interdit à la fonction de modifier les variables du Blueprint
Call In Editorajoute un bouton dans les Details d'une instance placée dans le niveau : lancer la fonction sans jouer (regénérer un décor, ranger des Actors)
Override / Parent:un Blueprint enfant redéfinit la fonction — voir Polymorphisme
Blueprint Function Libraryasset qui contient des fonctions statiques (sans instance), appelables depuis n'importe quel Blueprint : conversions, calculs utilitaires. Elles n'ont pas de self — tout ce dont elles ont besoin leur est passé en paramètre
Une fonction ne peut pas attendre

Delay, Timeline, AI Move To, Move Component To et tous les nœuds latents sont refusés dans une fonction (ils s'affichent avec une icône d'horloge, désactivés). Pour faire attendre quelque chose : mettre la partie « attente » dans un Custom Event, ou planifier la suite avec un timer — un Set Timer peut, lui, être appelé depuis une fonction, puisqu'il ne fait que programmer l'appel.

Du spaghetti à la fonction

Sélectionner les nœuds → clic droit → Collapse to Function : les entrées et sorties sont déduites des fils qui traversent la sélection. Nommer la fonction par ce qu'elle fait (ApplyDamage), pas par ce qu'elle contient.

Events & Custom Events

Un event est un point d'entrée de l'Event Graph : le moteur ou un autre nœud l'appelle, le flux blanc part de lui. Contrairement à une fonction, il peut attendre (nœuds latents) mais n'a pas de valeur de retour.

Event AnyDamagel'Actor reçoit des dégâts (Damage, Damage Type, Instigated By, Damage Causer)

Peut attendreoui : Delay, Timeline, AI Move To… fonctionnent

Un Delay ne s'annule pas

Une fois lancé, un Delay ne se stoppe pas, et si l'Actor est détruit entre-temps la suite ne s'exécute simplement jamais. Pour un délai qu'on veut pouvoir annuler, mettre en pause ou interroger : un timer.

Event Dispatcher & event handler

Un Event Dispatcher est un événement qu'un Blueprint annonce sans savoir qui écoute. D'autres Blueprints s'y abonnent et réagissent chacun à leur façon : c'est l'inverse d'un appel direct, l'émetteur ne dépend de personne. Le dispatcher annonce, le handler réagit.

Mise en place en quatre étapes

Étape Emplacement Action dans l'Éditeur & Code Rôle technique & Pièges
1. Déclarer Émetteur
(ex: BP_Boss)		 Panneau My Blueprint → section Event Dispatchers → bouton +. Nommer l'événement (ex: OnDeath). Ajouter des paramètres d'entrée dans les détails si nécessaire (ex: OnHealthChanged(NewHealth)). Définit la "signature" (les informations qui seront envoyées). À ce stade, le dispatcher est juste une boîte vide en attente d'abonnés.
2. Diffuser Émetteur Glisser le dispatcher dans le graphe et choisir Call. Relier ce nœud au moment fatidique (ex: quand la vie tombe à 0). Déclenche instantanément et simultanément la fonction de tous les Blueprints qui écoutent cet événement. Si personne n'écoute, le flux continue sans erreur.
3. S'abonner Abonné
(ex: WBP_HUD)		 À partir d'une référence valide de l'émetteur, tirer un fil et créer le nœud Bind Event to [Nom]. Relier la broche carrée rouge (Event) à un Custom Event créé pour l'occasion.
Astuce : Glisser le dispatcher depuis la référence et choisir Assign crée le nœud Bind et le Custom Event d'un seul coup.		 Le piège : Le nœud Bind doit absolument être exécuté par le flux blanc (ex: au Begin Play) pour que l'écoute commence. La signature du Custom Event connecté doit correspondre au millimètre près à celle déclarée à l'étape 1.
4. Se désabonner Abonné À partir de la référence de l'émetteur, utiliser le nœud Unbind Event from... ou Unbind All Events. Permet d'arrêter d'écouter l'émetteur. Essentiel pour la propreté du code ou pour éviter qu'un objet détruit ou désactivé ne continue de réagir en tâche de fond (fuites de mémoire logiques).

Les dispatchers du moteur s'utilisent de la même façon : On Component Begin Overlap, On Clicked (bouton), On Destroyed, On Take Any Damage… On s'y abonne par Bind Event to… ou Assign depuis la référence de l'objet. Le bon moment pour s'abonner est souvent BeginPlay (ou Event Construct pour un widget).

Macros

Une macro est un morceau de graphe réutilisable qui est recopié à chaque endroit où on l'utilise (inlining à la compilation). Son intérêt est ce qu'une fonction ne sait pas faire : plusieurs pins d'exécution en entrée et en sortie, comme un Branch.

AspectMacro
Pins d'exécutionautant d'entrées et de sorties que voulu (chacune nommée)
Donnéesentrées et sorties typées, y compris wildcard (type qui s'adapte au fil branché — c'est ce qui rend For Each Loop utilisable avec n'importe quel tableau)
Nœuds latentsDelay accepté, Timeline refusé
Où la créerMy Blueprint → Macros → + (locale à ce Blueprint), ou dans une Blueprint Macro Library (Content Browser → Blueprint → Blueprint Macro Library) pour la partager entre Blueprints. Le parent choisi à la création de la bibliothèque détermine les nœuds disponibles (un parent Actor donne accès aux fonctions d'Actor)
Appel depuis l'extérieurimpossible : pas de référence, pas d'override. Les macros du moteur (For Loop, Do Once, Is Valid…) sont dans la bibliothèque StandardMacros
ChoisirQuand
Macroun motif de flux (valider puis aiguiller vers plusieurs suites), répété à quelques endroits, dont on veut des sorties d'exécution multiples
Fonctionun calcul ou une action réutilisable, appelable de l'extérieur, surchargeable par un enfant, avec un seul chemin de sortie
Collapsed Nodeseulement ranger visuellement un graphe — rien n'est réutilisé
Une macro utilisée 40 fois, c'est 40 copies

Chaque usage ajoute son contenu au Blueprint : une grosse macro très répétée alourdit la compilation et le Blueprint. Dès qu'il n'y a plus qu'un seul chemin d'exécution à la sortie, une fonction est le bon choix.

Blueprint Macro Library

Une macro locale ne sert qu'à son Blueprint. Pour la partager, on la range dans une Blueprint Macro Library : un asset qui ne contient que des macros, visibles ensuite dans la palette de tous les Blueprints compatibles — comme For Each Loop ou Do Once.

ÉtapeComment
1. CréerContent Browser → Blueprint → Blueprint Macro Library, nommée BPML_Utils. Unreal demande une classe parente
2. Choisir le parentObject : utilisable dans tous les Blueprints, mais sans accès aux fonctions d'Actor. Actor : les macros peuvent appeler Get Actor Location, Destroy Actor… mais la bibliothèque ne se propose que dans les Blueprints qui héritent d'Actor
3. ÉcrireMacros → +, avec ses entrées / sorties d'exécution et de données, comme une macro locale. Une bibliothèque n'a ni variables membres, ni Event Graph
4. Utiliserclic droit dans un graphe compatible, chercher le nom de la macro. Elle apparaît comme un nœud avec ses pins d'exécution nommés

Macro Library, Function Library ou composant ?

La Macro Library partage du flux (plusieurs sorties d'exécution, nœuds latents, wildcards). La Function Library partage des calculs et des actions statiques avec une seule sortie. Un Actor Component partage un comportement avec un état (de la santé, un inventaire).

Modifier une macro recompile ses utilisateurs

Le contenu d'une macro est copié dans chaque Blueprint qui l'utilise : changer un pin de la bibliothèque oblige tous ces Blueprints à se recompiler, et peut casser leurs connexions. Figer le nom et les pins d'une macro partagée avant de l'utiliser partout.

Timers : Set Timer by Event / by Function Name

Un timer demande au moteur d'appeler un event ou une fonction dans X secondes, une fois ou en boucle — sans occuper l'Event Tick et sans bloquer un graphe. Il rend un Timer Handle qui permet de le retrouver pour le pauser, l'interroger ou l'annuler.

Set Timer by Eventune broche Event (delegate) : on y branche un Custom Event, ou un Create Eventle plus sûr : le lien est visuel, renommer le Custom Event ne casse rien
Set Timer by Function Nameun Object (par défaut self) et un Function Name saisi en textela fonction est cherchée par son nom à l'exécution : faute de frappe ou renommage = timer muet, sans erreur. Elle ne doit pas avoir de paramètres
ParamètreRôle
Timedélai en secondes (de jeu) avant l'appel — ou entre deux appels si Looping
Loopingcoché : rappelle toutes les Time secondes jusqu'à ce qu'on l'arrête ; décoché : un seul appel
Initial Start Delaydélai avant le premier déclenchement quand on le veut différent de Time (laissé à 0, le premier appel a lieu après Time)
Initial Start Delay Random Deviationaléa ± ajouté à ce premier délai — évite que cent ennemis créés ensemble tirent tous à la même frame

Time = 0 supprime le timer

Un Set Timer avec Time ≤ 0 annule le timer au lieu de le déclencher « tout de suite ». Pour exécuter à la frame suivante, voir La frame suivante.

Rappeler Set Timer le réarme

Appeler à nouveau Set Timer pour le même event (ou la même fonction) remplace le timer existant au lieu d'en ajouter un. C'est l'astuce « réinitialiser à chaque coup » : « la régénération démarre 5 s après le dernier coup reçu ».

Temps de jeu, pas temps réel

Les timers suivent le temps de jeu : ralentis par le time dilation (slomo, Set Global Time Dilation) et figés quand le jeu est en pause (Set Game Paused). Un timer en boucle plus court qu'une frame est appelé plusieurs fois dans la même frame pour rattraper son retard — éviter des durées inférieures à ~0,02 s.

Mettre en pause sans mettre le jeu en pause

Un menu d'inventaire ouvert qui doit figer un poison ou une recharge, sans arrêter le monde : Pause Timer by Handle à l'ouverture, Unpause Timer by Handle à la fermeture. Les effets reprennent avec le temps restant.

La frame suivante (next tick)

Besoin fréquent : « attendre que tout soit en place » — un Actor tout juste spawné, un widget créé, un autre Actor dont le BeginPlay n'a pas encore tourné. Attendre une seule frame suffit souvent.

BesoinOutil
Attendre une frame au milieu d'un eventDelay Until Next Tick (nœud latent : Event Graph, pas fonction ni macro à timeline)
Planifier un event ou une fonction à la frame suivante, y compris depuis une fonctionSet Timer for Next Tick by Event / by Function Name (selon la version du moteur ; en C++ : SetTimerForNextTick)
Écrire un Set Timer « immédiat »impossible : Time ≤ 0 annule le timer. Utiliser les outils ci-dessus
Un Delay de 0 secondeattend aussi jusqu'à la frame suivante, mais l'intention est moins lisible que Delay Until Next Tick
Quand c'est la bonne solution

Ordre d'initialisation : au BeginPlay, rien ne garantit qu'un autre Actor a déjà fini le sien ; attendre une frame avant de le lire. Après un spawn : laisser le nouvel objet terminer sa construction avant de le configurer. Réentrance : un event qui se rappelle lui-même immédiatement risque la boucle infinie ; le rappeler à la frame suivante la brise.
