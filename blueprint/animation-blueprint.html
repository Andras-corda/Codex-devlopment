3 · Animation Blueprint

Faire correspondre le mouvement du personnage (page précédente) à une animation cohérente : Blend Space pour mélanger, Animation Blueprint (ABP) pour piloter le tout.

Blend Space

Un Blend Space mélange plusieurs animations selon un ou deux paramètres continus (ex. la vitesse) — au lieu de choisir « soit Idle, soit Walk, soit Run », on obtient un mélange progressif entre elles.

1D2D
Paramètresun seul (ex. Speed)deux (ex. Speed + Direction)
Bon pourIdle → Walk → Run en ligne droiteajouter le strafe (déplacement latéral/arrière)

Animation Blueprint

Un Animation Blueprint pilote le SkeletalMeshComponent et se divise en deux graphes : l'Event Graph calcule des variables chaque frame, l'AnimGraph les utilise pour produire la pose finale.

Ne pas confondre les deux graphes

L'Event Graph tourne comme un Blueprint classique (nœuds d'exécution). L'AnimGraph est évalué en continu pour produire une pose — pas de notion d'ordre séquentiel, chaque nœud décrit « quelle pose produire à partir de ces entrées ».

Layered Blend per Bone

Le nœud Layered blend per bone combine deux poses par partie du squelette : la pose de base partout, et une pose « calque » à partir d'un os donné. C'est ce qui permet de viser ou d'attaquer avec le haut du corps pendant que les jambes continuent de courir.

RéglageEffet

Blend Depthfondu progressif sur plusieurs os au lieu d'une coupure nette à l'os de départ

Le montage n'apparaît pas

Play Anim Montage joue sur le Slot choisi dans le montage (Slot Name, ex. DefaultGroup.UpperBody). Si l'Animation Blueprint ne contient pas de nœud Slot du même nom, le montage joue « dans le vide » : aucune erreur, aucune animation visible. Le nœud Slot se place avant la sortie (ou comme source du calque, comme ci-dessus).

Save Cached Pose / Use Cached Pose

Une pose calculée (typiquement la State Machine de locomotion) peut être enregistrée sous un nom puis réutilisée à plusieurs endroits du graphe, sans être recalculée : elle n'est évaluée qu'une fois par mise à jour, quel que soit le nombre d'utilisations.

NœudRôle
Save cached pose « Locomotion »reçoit la pose en entrée et la mémorise sous ce nom ; il n'a pas de sortie et ne se branche pas sur Output Pose
Use cached pose « Locomotion »ressort la pose mémorisée, autant de fois qu'on veut (clic droit dans le graphe → chercher le nom)
Recette « locomotion + haut du corps »Nœuds
1. MémoriserState Machine « Locomotion » → Save cached pose « Locomotion »
2. BaseUse cached pose « Locomotion » → pin Base Pose d'un Layered blend per bone
3. CalqueSlot « UpperBody » → Blend Poses 0 (filtre spine_01)
4. Corps entiersortie du Layered blend → Slot « DefaultSlot » (montages plein corps, ex. roulade) → Output Pose
Pourquoi pas dupliquer la State Machine

Copier la State Machine en deux endroits la ferait tourner deux fois (coût doublé) et ses états pourraient se désynchroniser. Un cached pose garantit que tout le monde lit la même pose. Il vaut uniquement à l'intérieur du même Animation Blueprint.

Anim Notify & Notify State

Un notify est un marqueur posé sur la timeline d'une animation (ou d'un montage) : quand la lecture le franchit, il déclenche un événement. C'est la façon propre de synchroniser le gameplay sur l'animation — le pas qui touche le sol, l'instant où l'épée frappe — au lieu de compter des secondes dans un Delay.

Anim NotifyAnim Notify State
Duréeun instantun intervalle (début → fin)
ÉvénementsNotifyNotify Begin, Notify Tick, Notify End
Exemplespas qui touche le sol, son, particules, fin d'un couphitbox d'arme active, fenêtre de combo, invincibilité, traînée d'épée
Préfixe usuelAN_ANS_

Notify nomméAdd Notify → New Notify… puis un nom (FootstepL)événement AnimNotify_FootstepL dans l'Event Graph de l'Animation Blueprint — accès à ses variables et à Try Get Pawn Owner

Exemple : bruits de pas selon le sol

Un AN_Footstep posé sur chaque pas de la marche et de la course : il lance un Line Trace vers le bas depuis le pied, lit le Physical Material touché et joue le son correspondant. Chaîne complète dans Physical Material.

Quand un notify ne part pas

Mesh non évalué : un mesh hors champ ou sur un serveur dédié peut ne pas faire avancer ses animations — régler Visibility Based Anim Tick Option sur Always Tick Pose pour les notifies de gameplay (hitbox). Poids trop faible : une animation presque entièrement fondue ne déclenche pas ses notifies. Timing de combat : dans un montage, passer Montage Tick Type du notify sur Branching Point pour qu'il parte exactement à sa frame et non en fin de mise à jour. À régler aussi sur le notify : Notify Trigger Chance (probabilité) et Notify Filter LOD (ignorer les notifies cosmétiques sur les personnages lointains).

Retargeting d'animations (Mixamo)

Une animation est liée à un Skeleton : elle ne se joue que sur des personnages qui le partagent. Le retargeting convertit une animation d'un squelette vers un autre (autres proportions, autres noms d'os). Cas typique : des animations Mixamo à faire jouer sur le Mannequin d'Unreal.

Parfois, inutile de retargeter

Si on utilise le personnage Mixamo lui-même, ses animations Mixamo importées sur son Skeleton fonctionnent directement : aucun retargeting. On retargete seulement pour faire jouer ces animations sur un autre squelette (le Mannequin, un personnage acheté).

ÉtapeComment
1. Récupérersur Mixamo : le personnage en FBX With Skin (une fois), puis chaque animation en Without Skin. Cocher In Place pour les cycles de marche et de course (le déplacement vient du jeu, pas de l'animation)
2. Importerle personnage (crée Skeletal Mesh + Skeleton), puis les animations en choisissant ce même Skeleton. Si on s'arrête là, les animations jouent sur le personnage Mixamo
3. Un IK Rig par squeletteContent Browser → Animation → IK Rig, sur le mesh Mixamo puis sur le Mannequin. Définir le Retarget Root (le bassin : Hips / pelvis) et les Retarget Chains (colonne, bras, jambes, tête, doigts). La génération automatique des chaînes devine l'essentiel sur un humanoïde — à vérifier à la main
4. IK RetargeterAnimation → IK Retargeter : source = IK Rig Mixamo, cible = IK Rig Mannequin ; vérifier le Chain Mapping (chaque chaîne source vers sa chaîne cible)
5. Aligner les posesMixamo est en T-pose, le Mannequin UE5 en A-pose. Dans le retargeter, Edit Pose sur la cible jusqu'à ce que les deux personnages se superposent bras compris
6. Exporteronglet Asset Browser du retargeter : sélectionner les animations → Export Selected Animations (ou clic droit sur une animation → Retarget Animations). Elles existent désormais sur le Skeleton du Mannequin
7. Utiliserdans le Blend Space et l'Animation Blueprint du Mannequin
Les défauts classiques

Poses non alignées : bras de travers ou jambes qui se croisent — c'est presque toujours la T-pose contre la A-pose de l'étape 5. Pieds qui glissent ou flottent : proportions différentes ; activer l'IK des pieds dans le retargeter et vérifier que le Retarget Root est bien le bassin. Pas de root motion : Mixamo n'a pas d'os root ; avec In Place, on déplace le personnage par le code (Add Movement Input). Mauvais Skeleton : un Blend Space n'accepte que des animations du Skeleton auquel il est lié — importer ou exporter sur le bon.
