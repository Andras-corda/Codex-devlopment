3 · Concurrence

PHP n'est pas asynchrone par défaut, contrairement à C# ou JavaScript. Comprendre pourquoi, et ce que le langage offre quand même pour paralléliser.

Le modèle par défaut : bloquant, une requête = un script

Historiquement, chaque requête HTTP lance (ou réutilise via PHP-FPM) un processus qui exécute le script du début à la fin, séquentiellement. Un appel réseau (file_get_contents, une requête SQL) bloque ce processus jusqu'à la réponse — il n'y a pas d'event loop intégré comme dans Node.js ou de runtime async/await comme en C#.

Ce que ça change au quotidien

Le serveur web (PHP-FPM, Apache) absorbe la charge en lançant plusieurs processus PHP en parallèle pour plusieurs requêtes — mais à l'intérieur d'un seul script, un appel réseau après l'autre reste séquentiel, sauf à utiliser explicitement l'un des outils ci-dessous.

Paralléliser des appels réseau : curl_multi

Sans bibliothèque tierce, l'extension curl (native) permet de lancer plusieurs requêtes HTTP en parallèle et d'attendre l'ensemble.

Le plus proche de Task.WhenAll en C#

curl_multi_* est l'outil natif de référence pour « lancer N requêtes, attendre toutes les réponses » sans dépendance externe.

Générateurs — itération paresseuse

Un générateur (yield) produit ses valeurs une à la fois, à la demande, sans tout charger en mémoire — l'équivalent PHP du yield return / IEnumerable de C#. Ce n'est pas du parallélisme, mais c'est la brique qui permet d'écrire du code coopératif.

Fibers (PHP 8.1) — suspendre une fonction en cours

Une Fiber permet de suspendre l'exécution d'une fonction n'importe où (pas seulement à un yield de premier niveau) et de la reprendre plus tard — la brique bas niveau sur laquelle les bibliothèques asynchrones (ReactPHP, Amp) construisent leur async/await.

Une Fiber seule ne parallélise rien

Elle change quand le code s'exécute, pas combien de choses s'exécutent en même temps. C'est un outil pour bâtir un ordonnanceur asynchrone (comme le fait ReactPHP en interne), rarement utilisé directement dans du code applicatif.

Pièges & idées reçues

Idée reçueRéalité
« PHP peut faire de l'async/await comme C# »pas nativement — il faut une bibliothèque (ReactPHP, Amp, Swoole) qui gère sa propre boucle d'événements
« PHP-FPM = du parallélisme dans mon script »non : plusieurs requêtes différentes tournent en parallèle, pas plusieurs opérations d'un même script
« curl_multi suffit toujours »oui pour du HTTP, mais pas pour du calcul CPU pur (là, il faut des processus séparés ou l'extension parallel)
« un générateur tourne en arrière-plan »non : il s'exécute uniquement quand on itère dessus (foreach, next(), send())

Pour aller plus loin (hors de ce guide)

Sans sortir du PHP « pur », ce guide s'arrête aux outils natifs ci-dessus. Pour une vraie boucle d'événements et un async/await proche de celui de C#, l'écosystème propose des bibliothèques dédiées — aucune n'est requise pour le reste du site :

  • ReactPHP / Amp — boucle d'événements et primitives asynchrones en PHP pur
  • Swoole / OpenSwoole — extension C qui ajoute coroutines et serveur asynchrone
