Le système de types

PHP est dynamiquement typé : le type se détermine à l'exécution, pas à l'écriture. Les tableaux se comportent comme des types valeur (copiés), les objets comme des types référence (partagés) — détaillé sur la page Procédural.

Types scalaires

Type Détail Exemple
int entier, taille de la plateforme (64 bits en pratique) PHP_INT_MAX, 1_000_000, 0x1F, 0b1010
float virgule flottante double précision 3.14, 1.5e3
string chaîne de taille arbitraire, encodage libre (souvent UTF-8) "texte", 'texte'
bool true / false —

Conversions & type juggling

PHP convertit automatiquement les types aux endroits où c'est ambigu — pratique, mais source classique de bugs si on ne le sait pas.

== vs ===

Toujours préférer === / !== sauf besoin explicite de conversion. == a des règles historiques surprenantes (bien qu'améliorées en PHP 8).

Valeurs « falsy » & null

Dans un contexte booléen (if, &&…), plusieurs valeurs différentes de false sont tout de même considérées fausses.

isset vs empty vs is_null

isset($x) : existe et n'est pas null. empty($x) : n'existe pas, ou vaut une valeur « falsy ». is_null($x) : vaut exactement null (variable déjà déclarée). Dans le doute, ?? couvre la majorité des cas.

Types spéciaux

Type Rôle

Panorama

PHP n'a qu'une seule structure native pour « une collection » : le array. La SPL (Standard PHP Library) ajoute des structures spécialisées quand array ne suffit pas.

Structure Nature Pour…
array (liste) liste ordonnée, indices numériques l'usage par défaut — 90 % des cas
array (associatif) table clé → valeur, ordre d'insertion préservé dictionnaire, config, JSON décodé
Generator séquence paresseuse, un élément à la fois gros volumes, pagination, flux
SplStack / SplQueue pile (LIFO) / file (FIFO) dédiées quand la sémantique doit être explicite
SplObjectStorage ensemble/table dont les clés sont des objets associer une donnée à des objets sans spl_object_hash
ArrayObject enrobe un array pour le rendre orienté objet passer un « tableau » par référence à travers des objets

Clés

Les clés de tableau sont des int ou des string uniquement. Une clé numérique sous forme de chaîne ("3") est silencieusement convertie en entier (3).

Structures SPL

Interfaces de collection (SPL)

Comme List<T> implémente IList<T> en C#, les structures PHP implémentent des interfaces standard qu'on peut aussi adopter dans ses propres classes.

Style fonctionnel : l'équivalent de LINQ

PHP n'a pas de LINQ intégré, mais les fonctions array_* se combinent pour obtenir le même résultat.

Quelle structure choisir

Besoin Structure
cas général, liste ou dictionnaire array
gros volume, traitement au fil de l'eau Generator (yield)
pile / file avec une API explicite SplStack / SplQueue
associer une donnée à des objets SplObjectStorage / WeakMap
rendre une classe utilisable dans un foreach Iterator / IteratorAggregate
rendre une classe utilisable avec $obj[...] ArrayAccess

Rédiger de l'UML — la boîte de classe

Un diagramme de classes communique la structure d'un modèle. On y met ce qui aide à comprendre, pas chaque détail du code — la notation ne dépend d'aucun langage, seule sa traduction en code change.

Les relations — et leur traduction en PHP

Relation Notation Indice en PHP
Généralisation trait plein, triangle creux class B extends A
Réalisation trait pointillé, triangle creux class C implements Ix
Composition losange plein propriété instanciée dans __construct ; disparaît avec l'objet
Agrégation losange creux propriété passée au constructeur (injection) ; survit à l'objet
Association trait plein, flèche ouverte propriété typée vers l'autre classe
Dépendance trait pointillé, flèche ouverte type utilisé dans un paramètre / une variable locale

Générer l'UML en texte (Mermaid, PlantUML)

Mermaid (rendu par GitHub, GitLab, VS Code…) :

Symbole Mermaid / PlantUML Sens
héritage A <|-- B B hérite de A
réalisation A <|.. B B implémente A
composition A *-- B A possède B
agrégation A o-- B A référence B
association A --> B A connaît B
dépendance A ..> B A utilise B

Conseils de rédaction

  • Un diagramme = une intention. « Vue d'ensemble du domaine », « le sous-système de facturation »… pas « toutes les classes ».
  • Omettez le bruit : getters/setters triviaux, constructeurs, classes techniques (DTO, helpers).
  • Nommez les extrémités quand ce n'est pas évident : rôle et multiplicité (1, *).
  • Le sens des flèches compte : dessinez la navigation réelle (qui référence qui).
  • Préférez la composition à l'héritage dans le modèle — et le diagramme le montrera.
  • Gardez-le vivant : le texte (Mermaid/PlantUML) versionné avec le code vieillit mieux qu'une image.
