6 · Composer & Symfony

Le reste de ce guide PHP reste volontairement sans framework. Mais à un moment, on veut une bibliothèque que quelqu'un d'autre a déjà écrite — et là, on a besoin de Composer. Cette page couvre Composer seul, puis Symfony, le framework qui s'appuie dessus.

Composer, en bref

Composer est le gestionnaire de paquets de PHP (l'équivalent de npm pour JavaScript) : il installe des bibliothèques, gère leurs versions et leurs dépendances entre elles, et génère un autoloader qui charge automatiquement les classes sans require manuel. Rien de tout ça n'exige un framework.

Installer Composer

composer.json & autoload

Un fichier composer.json décrit le projet : version de PHP requise, dépendances, et comment trouver ses propres classes (autoload).

PSR-4

Convention : le namespace App\ correspond au dossier src/, donc App\Articles\ArticleModel se trouve dans src/Articles/ArticleModel.php. Plus besoin d'écrire un require par fichier comme dans le reste de ce guide.

Installer une bibliothèque

composer.lock se versionne, vendor/ non

composer.lock fige les versions exactes installées — à commiter, pour que toute l'équipe (et le serveur de prod) installe identique. vendor/ se régénère avec composer install et n'a pas sa place dans le dépôt : à lister dans .gitignore.

Passer à Symfony

Composer seul suffit pour ajouter des bibliothèques ponctuelles. Quand le projet a besoin de routage, d'un ORM, de formulaires, d'authentification et de tout faire cohabiter proprement, réécrire chaque brique à la main (comme dans Backend & MVC) devient répétitif. Symfony est un framework — installé lui aussi via Composer — qui fournit ces briques toutes faites.

Quand basculer

Pas un jugement de valeur

Pour un script, une API minuscule ou pour comprendre ce qui se passe sous un framework, le PHP pur du reste de ce guide reste le plus simple à lire de bout en bout — c'est pour ça qu'il est enseigné ainsi ici. Symfony gagne sa complexité quand le projet a plusieurs contributeurs, plusieurs dizaines de routes/entités, ou un vrai besoin d'authentification et de formulaires validés — la même logique que « procédural d'abord, objet quand ça grossit » vue précédemment.
