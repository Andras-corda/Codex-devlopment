1 · Bot Discord

Un bot Discord est un simple script Node.js qui reste connecté au serveur de Discord et réagit à des événements (message reçu, commande tapée…). La bibliothèque de référence : discord.js.

Comment ça marche

Créer l'application Discord

  1. Créer l'application sur le portail développeur Discord → « New Application ».
  2. Onglet Bot → « Reset Token » pour obtenir le token — la clé secrète qui authentifie ton script. Ne jamais le partager ni le committer.
  3. Activer les intents nécessaires dans ce même onglet (ex. Message Content Intent pour lire le texte des messages).
  4. Inviter le bot : onglet OAuth2 → URL Generator → cocher bot (+ applications.commands pour les commandes slash) et les permissions requises → ouvrir l'URL générée.

Installer discord.js

Le client

Le Client représente ton bot. Les intents déclarent à l'avance quels événements il veut recevoir (moins d'intents = moins de trafic, plus rapide).

Réagir aux messages

Commandes textuelles vs slash

Les commandes tapées (!ping) exigent l'intent Message Content, limité par Discord pour les gros bots. Les commandes slash ci-dessous sont la méthode moderne recommandée — elles n'ont pas cette limite et s'affichent avec autocomplétion dans Discord.

Commandes slash

Une commande slash se déclare (son nom, sa description, ses options), s'enregistre une fois auprès de Discord, puis se traite via l'événement interactionCreate.

Organiser les commandes

Passé quelques commandes, tout entasser dans interactionCreate devient illisible. Motif courant : un fichier par commande, exportant son nom et sa fonction d'exécution, chargés dans une Collection.

Variables d'environnement

Le token, c'est un mot de passe

Quiconque a le token contrôle entièrement le bot. Il vit dans .env (jamais commité — l'ajouter au .gitignore), lu via process.env.DISCORD_TOKEN, jamais écrit en dur dans le code.

Héberger le bot

Le script doit rester en cours d'exécution en permanence — une machine personnelle éteinte coupe le bot. Options courantes : un petit VPS avec pm2 (relance automatique si le script plante), ou une plateforme comme Railway/Render.
