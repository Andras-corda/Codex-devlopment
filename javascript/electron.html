Electron empaquette Chromium (pour l'affichage) et Node.js (pour le système) ensemble : une application de bureau écrite en HTML/CSS/JS, qui tourne sur Windows, macOS et Linux depuis un seul code.

Deux processus, un rôle chacun

C'est le concept à comprendre en Electron : le code ne tourne jamais dans un seul contexte.

Le processus principal

Le renderer

Une page HTML tout à fait ordinaire — elle ne peut pas faire require('fs') ni import de module Node directement, seulement ce que preload.js lui expose.

preload.js & contextBridge

Le pont sécurisé : preload.js tourne avec un accès limité à Node, et n'expose au renderer que ce qu'on choisit explicitement via contextBridge — jamais Node.js en entier.

Communication IPC

ipcRenderer.invoke (renderer → main, avec réponse) se traite côté main par ipcMain.handle ; pour un envoi sans réponse attendue, ipcRenderer.send / ipcMain.on.

Le réflexe qui évite 90 % des bugs de sécurité Electron

contextIsolation: true et nodeIntegration: false restent activés (ce sont les valeurs par défaut depuis longtemps — ne jamais les désactiver « pour aller plus vite »). Toute capacité système passe par un canal IPC explicite dans preload.js, jamais par un accès direct à Node depuis la page.
