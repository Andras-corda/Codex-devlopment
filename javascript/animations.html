Transitions

Une transition anime un changement de valeur existant — pas de séquence à décrire, juste « comment passer de l'ancienne à la nouvelle valeur ».

transform — et pourquoi c'est le bon choix pour animer

Performance : animer transform/opacity, pas width/top/margin

transform et opacity se calculent sur le GPU, sans recalculer la mise en page de la page (« reflow »). Animer width, top ou margin force le navigateur à recalculer tout l'agencement à chaque image — plus saccadé, surtout sur mobile.

Animations avec @keyframes

Pour une séquence à plusieurs étapes, indépendante d'une interaction (chargement, pulsation, apparition automatique).

PropriétéRôle

animation-fill-mode: forwardsgarde l'état final après la fin (sinon ça « saute » au style d'origine)

JavaScript : requestAnimationFrame

Quand une transition/animation CSS ne suffit plus (logique par image, valeur qui dépend d'un calcul) : requestAnimationFrame planifie un rappel juste avant le prochain rafraîchissement d'écran — fluide, et mis en pause automatiquement sur un onglet caché.

Web Animations API

L'équivalent programmable de @keyframes — utile pour construire une animation dont les valeurs dépendent de données, et pour la contrôler (pause(), reverse(), écouter sa fin).

Animer au scroll : IntersectionObserver

Détecte quand un élément entre dans la zone visible, sans écouter l'événement scroll (coûteux). Le motif « révéler au scroll » quasi universel sur le web aujourd'hui.

Respecter prefers-reduced-motion

Certains visiteurs désactivent les animations (confort, santé — vertiges/migraines). Toujours prévoir une version sans mouvement.
