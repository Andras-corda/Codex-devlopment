Node.js comme serveur : répondre à des requêtes HTTP, parler à une base de données, exposer une API. Avec Express, le framework minimal qui domine l'écosystème.

Node.js comme serveur

Node fournit un module http natif — capable de servir des requêtes sans aucune dépendance — mais tout le monde (ou presque) passe par Express, qui ajoute routage et middleware par-dessus.

Middleware

Une fonction (req, res, next) qui s'exécute avant la route — pour parser le corps de la requête, journaliser, authentifier… next() passe la main au middleware ou à la route suivante.

MéthodeRôle

res.status(code)fixe le code HTTP (chaînable : .status(404).json(...))
res.send(texte)répond en texte/HTML brut
res.redirect(url)redirection HTTP

Connexion à une base de données

Comme pour PDO côté PHP : une connexion, et des requêtes paramétrées — jamais de concaténation d'une valeur utilisateur dans le SQL.

CRUD complet

Organiser en couches

Express n'impose aucune structure — le motif le plus courant reprend les mêmes rôles que le MVC vu côté PHP : routes (contrôleur), fonctions d'accès aux données (modèle), réponses JSON (pas de « vue » HTML pour une API).

Gestion des erreurs

Un middleware à 4 paramètres (avec err en premier) capte les erreurs — à déclarer en dernier, après toutes les routes.

Sécurité de base

RisqueParade
Injection SQLrequêtes paramétrées — jamais de template string dans une requête
Secrets exposés.env + dotenv, jamais commité
En-têtes manquantshelmet() (CSP, X-Frame-Options…)
Requêtes cross-origin non désiréescors() avec une liste d'origines explicite
Trop de requêtes (abus)express-rate-limit sur les routes sensibles
